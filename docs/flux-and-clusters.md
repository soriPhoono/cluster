## Testing mirrors production

The **k3d** workflow (`nix run` in this flake) bootstraps Flux with path `./k3s/clusters/testing`. Production **k3s** is expected to use the **same** path and the same `k3s/infrastructure` tree so there is a single source of truth. The directory name `testing` means “Flux bootstrap entrypoint for this layout,” not a throwaway stack unrelated to prod.

## Bootstrap and remote

[`../k3s/clusters/testing/flux-system/gotk-sync.yaml`](../k3s/clusters/testing/flux-system/gotk-sync.yaml) defines the `GitRepository` URL and branch. Files under `flux-system/` may be partially generated by `flux bootstrap`; treat them with care when merging.

## Dependency order

[`infrastructure.yaml`](../k3s/clusters/testing/infrastructure.yaml) applies `infra-controllers` first (`./k3s/infrastructure/controllers`). A second `Kustomization` for `./k3s/infrastructure/configs` can be uncommented when you add manifests that must run after controllers (and optionally `dependsOn: infra-controllers`).
